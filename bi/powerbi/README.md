# Power BI: Cold Tier Analytics

A one-page Power BI report over the **Parquet cold tier** (`data/cold/`),
generated by code. The web dashboard (`python tasks.py web`) shows data
arriving *now*; this report shows what was *kept*, analysed afterwards.

**The point to make when presenting:** Power BI reads the archive files
directly. Nothing is exported or copied for it, because the cold tier is an open
format that any tool can query, not only this project's code.

## Open it

```bash
python tasks.py demo      # if data/cold/ is empty
python tasks.py powerbi   # builds the report and opens it in Power BI Desktop
```

Then click **Home > Refresh** once to load the data. The report ships without
data and reads it from the Parquet files on refresh. If Power BI asks about
privacy levels or file access, allow it.

Run `python tasks.py powerbi` again after new demo runs, or just click Refresh.

## What's on the page

| Visual | Answers |
|---|---|
| 4 cards: Total Spans · Total Tokens · Tenants · p95 TTFT | How big is the archive? |
| Column chart: tokens by model | Which models do the most work? |
| Bar chart: top 10 tenants by tokens | Who uses the most? |
| Table: model · spans · p95 TTFT · error % | How does each model perform? |
| Donut: spans by status | How many requests failed, and how? |
| Slicers: model, date | Filter everything above |

Spans with no model are an agent calling a tool (search, SQL, code). They are
labelled **agent tool call** and left out of the latency figure, since they have
no time-to-first-token.

## How it's built

| File | Role |
|---|---|
| `spans.pq` | Power Query that loads every Parquet file into one table |
| `theme.json` | Colours matching the web dashboard |
| `../../scripts/build_powerbi.py` | Writes the Power BI Project: model, measures, layout |

The output goes to `bi/powerbi/build/` and is not committed, because it holds
this machine's absolute path to the data.

## Check the numbers

With no slicers set, the four cards should match DuckDB reading the same files:

```bash
telemetry-engine cold query "SELECT count(*) AS spans, sum(input_tokens + output_tokens) AS tokens, count(DISTINCT tenant_id) AS tenants, round(quantile_cont(ttft_ms, 0.95) FILTER (WHERE model <> ''), 1) AS p95_ttft_ms FROM spans"
```

## How to explain it in one breath

> "Hot data lives in ClickHouse for 48 hours. Before it expires we archive it as
> Parquet files, sorted for fast filtering. Power BI reads those files directly,
> so this is the long-term view: which models and tenants used the most tokens,
> how fast the models were, and how many requests failed."
